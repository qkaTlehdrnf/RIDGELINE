# Ridgeline

고지대 시야와 전장의 안개가 있는 작은 RTS 환경. 사람이 아니라 **LLM 에이전트가 실시간으로 지휘**하도록 설계했다.
유닛, 진영, 이름, 지도는 모두 이 프로젝트에서 새로 만든 것이며 표준 라이브러리만 쓴다 (Python 3.10+).

## 빠른 시작

```bash
python tests/test_core.py                         # 핵심 규칙 테스트
python -m ridgeline.match out.json                # 스크립트 봇끼리 한 판 (약 7초), 리플레이 저장
python tools/make_replay.py out.json out.html     # 리플레이를 단독 HTML 뷰어로
python tools/bench_tokens.py                      # 관측 형식별 토큰량 비교

# 실시간 대전: 게임은 벽시계로 흐르고 LLM은 준비될 때마다 관측하고 명령한다
python -m ridgeline.server --speed 1 --p1 bot &   # http://127.0.0.1:8765/ 에서 실시간 관전
python agents/llm_agent.py --player 0 --model claude-fable-5-2 --log runs/my.log
```

## 게임 규칙 요약

- 64x64 타일, 고도 3단계 (0 저지, 1 중간, 2 고지). 지상 유닛은 **경사로로만** 고도를 바꾼다.
- **시야**: 자기보다 높은 타일은 볼 수 없고, 사이에 더 높은 지형이나 덤불이 있으면 가려진다. 고지는 아래를 내려다보고 저지는 위를 못 본다.
  위쪽 목표를 쏘려면 아군 누군가의 시야가 필요하고 원거리 피해는 75%가 된다. 사격하면 2초간 위치가 드러난다.
  비행 정찰기(fly)는 지형을 무시하고, 감시탑(tow)은 자기 타일보다 한 단계 높게 본다.
- **전장의 안개**: 지형은 알려져 있지만 적 유닛은 보일 때만 관측된다. 적 건물은 마지막으로 본 위치를 기억한다.
- **경제**: 일꾼이 광석을 캐서 본부로 나른다. 건물이 유닛을 생산하고 보급 한도가 있다.
- **승리**: 적 건물을 모두 파괴. 30분(18000틱)이 지나면 병력과 자원 가치가 높은 쪽.
- 유닛 5종 `wrk inf hvy art fly`, 건물 5종 `hq dep bar wks tow`. 수치는 `ridgeline/data.py`.
- 진영 2개: **Aurum** (체력 +10%, 속도 -5%, 중장갑, 넓은 포격 범위) / **Sable** (체력 -10%, 속도 +10%, 전투 유닛이 10% 싸고 빠르게 생산, 정찰기에 약한 무장).
- 지도 `twin-shelf`: 본진은 고지, 앞마당은 중간 높이, 중앙에 정상(고지)이 있는 언덕, 양옆에 확장 능선. 180도 점대칭.

## LLM 인터페이스 (핵심)

플레이어마다 `Session` 하나 (`ridgeline/iface.py`). 같은 기능이 HTTP로도 열려 있다 (`ridgeline/server.py`).

| 호출 | HTTP | 용도 |
|---|---|---|
| `brief()` | `GET /brief` | 규칙, 유닛표, 지역/경사로 그래프, 명령 문법. **한 번만** 보내고 프롬프트 캐시에 둔다 |
| `obs("full")` | `GET /obs?mode=full` | 아는 것 전체의 압축 텍스트 |
| `obs("delta")` | `GET /obs` | 직전 호출 이후 **바뀐 줄과 새 이벤트만** |
| 없음 | `GET /wait?timeout=20` | 중요한 일(피격, 적 발견, 손실, 경고)이 생기면 즉시, 아니면 timeout에 delta 반환 |
| `act(text)` | `POST /act` | 명령 여러 줄 실행, 결과는 `ok N`과 실패한 줄만 |
| `query(text)` | 명령 줄 `q ...` | 필요할 때만 세부 정보 (지도 일부, 유닛, 경로, 건설 위치 등) |
| `set_script()` | `POST /script` | 엔진 안에서 몇 틱마다 도는 반사 스크립트 설치 |
| `obs_json()` | `GET /json` | 장황한 JSON 전체 상태 (스크립트 봇, 비교 기준용) |

토큰을 아끼는 장치들:

1. **분대 단위 집계**: 유닛을 하나씩 나열하지 않고 `A main inf×12 hvy×2 art×6 @30,22/R0 hp90 amove>38,19 ids 87,123-140` 처럼 묶는다. 유닛 수가 늘어도 줄 수는 거의 그대로다.
2. **증분 업데이트**: 줄마다 키가 있어서 바뀐 줄만 다시 보낸다. 좌표는 정수, 체력은 10% 단위라 사소한 변화로 줄이 바뀌지 않는다.
3. **이벤트 기반 깨우기**: 모델이 `wait 20`처럼 다음 차례를 스스로 정하고, 서버는 중요한 사건이 있을 때만 일찍 깨운다.
4. **질의형 API**: 지도 그림이나 유닛 상세는 `q map 20 40 44 60`, `q path ...`, `q site bar 12 50` 로 필요할 때만 받는다.
5. **의미 단위 위치**: 지역 `R7`, 경사로 `r14`, `home`, `enemy`, `#엔티티` 를 좌표 대신 쓸 수 있다. `build`는 근처의 합법 위치로 자동 보정된다.
6. **자동화 위임**: `auto wrk 16`, `auto sup on`, `repeat bar inf`, `rally` 로 경제를 맡기고, 반응 속도가 필요한 것은 반사 스크립트(`def tick(api)`)로 엔진 속도로 돌린다.

관측 예시 (delta 한 번):

```
t4472 ore650+295 sup88/112
B bar#202 23,59
B dep#231 30,54 con0
A main inf×12 hvy×2 art×6 fly×1 @30,22/R0 hp90 idle ids 87,123,134,140,...
X 4381 built bar#202 | 4408 built tow#213 | ready art×2 inf×4
```

명령 문법은 `brief()` 출력의 COMMANDS 절이 기준이다.

## 측정 결과

`tools/bench_tokens.py` (봇 대 봇 한 판, 10초마다 관측, 토큰은 추정치이며 형식 간 비율이 의미 있음):

| 형식 | 평균 | 최대 |
|---|---|---|
| 장황한 JSON 전체 | 약 4000 | 약 8500 |
| 압축 텍스트 전체 | 약 200 | 약 590 |
| 압축 텍스트 delta | 약 40 | 약 140 |

브리프는 약 1700 토큰이고 한 번만 보낸다.

실제 LLM 실시간 대전 (`runs/`):

- `live1` Fable 대 스크립트 봇, 1배속: **Fable 승** (5140틱, 35턴, 턴당 응답 약 6~7초). 리플레이 `runs/live1_fable_vs_bot.html`, 대화 기록 `runs/live1.log`.
  이 판은 분대 집계 버그를 고치기 전이라 후반 관측이 컸다 (그 기록에서 버그를 찾아 고쳤다). CLI 기준 비용 약 9.3달러.
- `live2` Haiku 대 스크립트 봇, 2배속: Haiku 패 (11턴밖에 못 두고 밀림). 수정 후 턴당 새 입력은 약 170~700 토큰.

## 구조

```
ridgeline/data.py     유닛, 건물, 진영 수치
ridgeline/mapgen.py   지도
ridgeline/engine.py   엔진 (시야, 경로, 전투, 경제)
ridgeline/iface.py    LLM 인터페이스 (브리프, 관측, 명령, 질의, 자동화, 반사 스크립트)
ridgeline/match.py    락스텝 실행기 (빠른 결정적 대전, 리플레이)
ridgeline/server.py   실시간 HTTP 서버 + 관전
agents/llm_agent.py   claude CLI로 지휘하는 실시간 에이전트
bots/basic.py         같은 텍스트 명령으로 두는 스크립트 봇
tools/                뷰어, 리플레이 변환, 토큰 벤치
```

## 알려진 한계

- 같은 진영, 같은 봇의 미러전이 완전한 무승부가 아니다 (처리 순서와 대형 배치에 미세한 비대칭). 진영 밸런스도 아직 조정 전이다.
- 반사 스크립트의 제한된 builtins는 실수 방지용이지 보안 경계가 아니다. 신뢰할 수 없는 코드를 돌리려면 프로세스 격리가 필요하다.
- LLM 연결은 `claude` CLI만 구현했다. CLI는 턴마다 고정 오버헤드가 있어서 API 직접 호출과 프롬프트 캐시를 쓰면 더 싸진다.
- 유닛끼리 충돌하지 않는다 (정지 유닛만 서로 밀어냄). 지도는 하나뿐이다.
